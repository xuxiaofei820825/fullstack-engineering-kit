# 前后端契约与联调规范

仅在变更同时影响前端与后端，或一侧的契约变化需要另一侧适配时读取。

## 契约优先

实现前明确并核对：

- HTTP method、资源路径、自定义动作和 URL 前缀。
- 路径参数、查询参数、请求头、Request body 与 Response body。
- 创建、更新和资源响应使用的对象边界；前端不得提交只读或服务端生成字段。
- 分页结构、页码起点、page size 限制、过滤和排序表达式。
- 枚举 code、时间格式和时区、空值与缺失字段语义。
- 错误码、HTTP 状态、错误消息展示方式和异常恢复行为。
- 认证方式、权限码、路由/按钮可见性和后端强制授权。
- 写操作的 revision/version、`updateMask`、操作者来源、幂等和冲突处理。

以前后端实际代码和 OpenAPI 契约为依据。发现契约不一致时先确定期望契约，再分别修改两侧；不要通过前端兼容猜测或后端临时透传掩盖差异。

## 实现顺序

1. 确定领域行为、资源模型、请求响应和错误状态。
2. 完成后端用例、领域规则、持久化、权限、迁移和后端测试。
3. 确认 OpenAPI 与实际 handler、VO 和错误结构一致。
4. 更新前端 Service 类型与请求函数，再实现页面、组件、权限和交互状态。
5. 分别运行前端与后端验证，再执行契约核对和可用时的联调或端到端验证。

如果变更可以安全并行实现，仍应先固定共享契约，并为契约变化指定单一事实来源。

## 联调检查

- 请求方法、路径、参数位置和字段名一致。
- Response 类型、分页、枚举、时间和错误结构一致。
- 前端 loading、empty、error、成功反馈和冲突反馈符合后端行为。
- 前端 access 规则与后端授权一致，但不替代后端校验。
- 写操作正确传递 revision、`updateMask` 和必要上下文；操作者不从不可信 body 获取。
- 危险操作有确认和防重复提交，后端具备幂等或并发保护。
- 后端契约测试和前端 Service 测试都断言完整请求响应契约。

## 完成标准

交付说明分别列出前端、后端、契约和数据变更，并记录：

- 前后端各自的验证命令与结果。
- 是否执行联调或端到端验证；未执行时说明原因。
- 数据迁移、兼容窗口、权限、安全和并发风险。
- 尚未解决的契约差异或后续工作。
